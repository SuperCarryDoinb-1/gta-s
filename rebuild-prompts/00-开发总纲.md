# 00 · 开发总纲(整个项目全程遵守)

你将分阶段实现一个浏览器开放世界游戏原型(GTA-like):程序化城市、昼夜天气、
驾驶/骑行/游泳/开船/坦克、行人与交通 AI、武器、通缉系统、生命值、经济闭环、主线剧情。
本总纲在**所有后续阶段**持续有效,任何阶段的实现不得违反这里的架构约定。

## 技术栈(版本固定,不要换)

```json
{
  "dependencies": {
    "@dimforge/rapier3d-compat": "^0.19.3",
    "three": "^0.185.1"
  },
  "devDependencies": {
    "@types/three": "^0.185.1",
    "typescript": "~6.0.2",
    "vite": "^8.1.1"
  },
  "scripts": { "dev": "vite", "build": "tsc && vite build", "preview": "vite preview" }
}
```

- 纯 TypeScript(strict 模式),无框架、无状态库、无 React。
- vite.config.ts 仅需 `optimizeDeps: { exclude: ['@dimforge/rapier3d-compat'] }`
  (rapier3d-compat 的 WASM 以 base64 内嵌,无需 wasm 插件)。
- tsconfig 关键项:`target: es2023`、`moduleResolution: bundler`、`strict: true`、
  `allowImportingTsExtensions: true`、`verbatimModuleSyntax: true`、`noEmit: true`、
  `noUnusedLocals/noUnusedParameters: true`。import 语句**带 .ts 扩展名**。

## 主循环架构(铁律)

Engine 驱动,`main.ts` 通过 `setHooks` 注入:

- `fixedUpdate(60Hz 固定步长)`:各实体 `beginStep`(记录插值端点、AI 决策、写物理输入)
  → `physics.step()` → 各实体 `endStep`(采样物理结果)。
- `update(每渲染帧)`:玩法系统轮询、`syncVisual(alpha)` 按插值系数混合前后两个物理步的位姿
  (**任何 60Hz 直读渲染都会在高刷屏上抖,必须插值**)、UI/音频刷新。

## 解耦约定(铁律)

gameplay 系统之间**不互相 import 实例**;跨系统事件用公开回调字段
(如 `weapons.onCrime`、`pedestrians.onHitByPlayerCar`、`vehicle.onExploded`),
统一在 `main.ts` 接线——看 main.ts 就能读出全部系统交互。

## 性能约定(铁律)

- **对象池**:行人/交通车/警力/曳光/烟火/现金全部固定池复用,运行期零常态分配。
  传给 Rapier `setLinvel` 等的参数对象也要模块级复用,避免 GC 峰值掉帧。
- **世界流式加载**:LOAD_RADIUS=2(240m 见方),远处没有物理地面——任何"远程放置实体"
  都要考虑踩空;剧情奖励载具用 `setStashed`(物理禁用+隐藏)暂存。
- **载具即插槽**:玩家"抢车"不生成新载具,而是主车瞬移换装(`teleportTo`+`setCarType`),
  AI 车原地变成停放的旧车——所有权模型 O(1)。
- 建筑等静态几何按 chunk 合并(merge geometry),减少 draw call。

## 编码规范

- 每个系统一个类,构造时注入依赖(scene、physics 等),公开回调字段解耦。
- 可调数值一律提升为**文件顶部大写常量**,便于调参。
- 注释用中文,简洁,只解释"为什么"。
- 每阶段完成必须 `npm run build`(含 tsc)零报错,浏览器 console 零报错。

## 验收方式

每个阶段文件末尾有验收清单。完成后:启动 `npm run dev`,在浏览器逐条核对通过再进入下一阶段;建议每阶段 git commit 一次。
